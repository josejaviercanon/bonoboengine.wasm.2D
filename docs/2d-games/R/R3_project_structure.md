## Key Principles

**`Game.Engine` holds the entire authoritative simulation** with zero UI/platform dependencies. No Razor, no Blazor, no platform API references. Components are Arch `struct` value types. Systems are stateless `[Query]`-attributed Arch systems.

**`Game.Engine.Generators` enforces the zero-copy float32 layout contract.** Roslyn analyzer errors on stride mismatch (`BNOBO001`) and unsupported field types (`BNOBO002`). Source generator emits `GeneratedSignalLayout` + `[ModuleInitializer]` static assert that cross-checks against `SignalBufferLayout` at WASM boot, plus the TypeScript half to `src/Game.UI/Frontend/scenes/generated/signalLayout.ts`.

**`Game.UI` is the presentation layer — a plain C# class library, not Razor.** Vite/Tailwind bundles PixiJS TypeScript to `wwwroot/dist`. It is a mirror of engine state via push-based delta events and shared-memory float arrays. `bufferLayout.ts` imports generated stride constants — never hand-maintained.

**Zero-copy transform bridge is mandatory.** High-frequency 2D transforms cross the WASM-JS boundary via pinned `GCHandle` buffers projected as `Float32Array` views over `WebAssembly.Memory.buffer`. No per-entity `[JSImport]` calls, no JSON serialization, no string marshalling in hot loops.

**Fixed-timestep physics decoupled from variable render ticks.** `Box2D.NET` steps and Arch ECS updates run inside a deterministic accumulator loop. Browser `requestAnimationFrame` drives only the PixiJS render pass reading shared memory.

## Host Platforms

Ship one browser-wasm host: **`Game.Wasm`** (non-Blazor).

### Game.Wasm (Microsoft.NET.Sdk.WebAssembly)

Direct `.NET WebAssembly` host bootstrapped via `import { dotnet } from './_framework/dotnet.js'` — no `blazor.webassembly.js`. Implements `[JSImport]`/`[JSExport]` interop bridge with:

- **`PinnedRenderBuffer`**: `GCHandle.Alloc(transformArray, GCHandleType.Pinned)` — single float32 buffer pinned for zero-copy reads
- **`WasmInterop`**: Typed command exports (spawn entity, apply impulse, set paused) passing only `int`, `float`, `bool` primitives
- **`wasm-interop.js`**: PixiJS provider side — projects `Float32Array` over `WebAssembly.Memory.buffer` and updates sprite pools in batch

Simulation loads lazily per visited scene via `Game.Examples` catalog (`ExamplesCatalog.cs` + `IExampleSims`).

```xml
<!-- Game.Wasm.csproj (excerpt) -->
<Project Sdk="Microsoft.NET.Sdk.WebAssembly">
  <PropertyGroup>
    <TargetFramework>net10.0</TargetFramework>
    <OutputType>Exe</OutputType>
    <NativeAot>true</NativeAot>
    <!-- No Blazor, no JS interop layers beyond [JSImport]/[JSExport] -->
  </PropertyGroup>
  <ItemGroup>
    <ProjectReference Include="..\Game.UI\Game.UI.csproj" />
    <ProjectReference Include="..\Game.Examples\Game.Examples.csproj" />
  </ItemGroup>
</Project>
```

> **No Blazor, no Razor, no SSR, no MAUI.** `Game.Maui` is temporarily commented out of the solution (web-only builds for speed). No `Game.Web` exists. The only host is `Game.Wasm` running directly in the browser via WASM Native AOT.

### Build & Run

```bash
# Frontend assets first (from src/Game.UI)
npm ci
npm run build        # DEFAULT: single-player co-located bundle

# .NET solution (from repository root)
dotnet build bonoboWebGame.slnx
dotnet test          # Game.Tests (xUnit v3) + Game.Tests.Aot (TUnit); MTP runner via global.json

# Run browser-wasm host
dotnet run --project src/Game.Wasm

# Playwright E2E (from src/Game.Tests.UI — Node project)
npm ci
npx playwright test        # boots Game.Wasm via dotnet run on port 5902
npm run typecheck
```

> **Frontend first.** Run `npm run build` in `src/Game.UI` before `dotnet build` so static web assets are present. Never run multiple `dotnet` commands concurrently (static-web-asset compression can race).
> **Generated output.** `wwwroot/dist` is produced by Vite/Tailwind — never hand-edit or commit it.
> **Kill stale hosts.** After touching `Game.UI` frontend assets, kill any running `Game.Wasm.exe` before rebuilding. 500s on `dist/*` = stale/raced output from `CopyGameUIAssets` MSBuild target; fix by killing the host and rebuilding (delete `src/Game.Wasm/bin`+`obj` if it persists).
